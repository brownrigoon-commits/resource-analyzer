# 자원 분석기

Windows PC의 CPU·메모리·디스크·GPU 사용량을 프로그램별로 확인하고 기록하는 로컬 앱입니다. 브라우저에서 실시간 사용량과 추이를 비교할 수 있습니다.

## 사용하기

1. [GitHub Releases](https://github.com/brownrigoon-commits/resource-analyzer/releases)에서 Windows용 `ResourceAnalyzer.exe`를 다운로드합니다.
2. 앱을 실행하면 Chrome 등 기본 브라우저에서 시작 화면이 열립니다.
3. **내 컴퓨터 분석하기**를 누르면 분석 화면이 열립니다.

지원 대상은 **Windows 10/11 x64**입니다. 배포 실행 파일에는 실행 환경이 포함되므로 Python을 별도로 설치하지 않아도 됩니다. 현재 배포 파일에는 코드 서명이 없습니다. 내려받은 파일의 출처와 릴리스 정보를 확인해 주세요.

앱이 실행 중이면 이 PC의 브라우저에서 [분석기 열기](http://127.0.0.1:7442/)로 다시 접속할 수 있습니다. 브라우저 탭을 닫아도 앱이 실행 중이면 기록은 계속됩니다. PC를 재부팅한 뒤에는 앱을 다시 실행해야 합니다.

웹사이트만으로 PC 전체의 성능을 읽는 방식은 아닙니다. 설치한 로컬 앱이 Windows의 측정값을 수집하고, 같은 PC의 브라우저가 화면을 표시합니다.

## 확인할 수 있는 정보

- 약 1초 간격으로 새로 측정하는 CPU·메모리·디스크·GPU 사용량
- 프로그램별 CPU·메모리·GPU 엔진·입출력 사용량
- 최근 60초 실시간 그래프와 1시간·24시간·7일 기록
- 15초 단위 요약 저장과 CSV 내보내기
- 지속적인 높은 사용률, RAM·GPU 전용 메모리 여유를 살펴볼 수 있는 안내

수집 시간이 길어지거나 시스템이 바쁘면 실제 갱신 간격이 늘어날 수 있습니다. 숫자가 같더라도 새 측정값일 수 있습니다.

## 측정값을 읽는 방법

| 항목 | 의미와 범위 |
| --- | --- |
| CPU | PC 전체 논리 프로세서 용량을 100%로 표시합니다. 프로그램의 CPU 사용률도 같은 기준입니다. |
| 메모리 | 사용 중인 RAM과 사용 가능한 RAM을 표시합니다. 프로그램별 작업 메모리 합계와 PC 전체 사용량은 같지 않을 수 있습니다. |
| 디스크 | PC 전체의 물리 디스크 처리량과 프로그램별 논리 입출력은 다른 지표입니다. 캐시·장치 입출력 등으로 합계가 일치하지 않을 수 있습니다. |
| GPU 전체 | NVIDIA 드라이버가 제공하는 사용률·전용 메모리·온도 등을 읽습니다. NVML을 우선 사용하고 필요하면 `nvidia-smi`를 이용합니다. AMD GPU 전체 지표는 현재 제공하지 않습니다. |
| 프로그램별 GPU | Windows GPU Engine 카운터에서 확인되는 프로세스의 엔진 사용량입니다. GPU 전체 지표와 기준이 달라 합계가 일치하지 않을 수 있습니다. 읽을 수 없는 값은 미지원 또는 확인 불가로 표시합니다. |
| 용량·속도 | 용량은 GiB, 입출력 속도는 MiB/s 기준입니다. 저장 공간 부족과 디스크 처리 속도 부족은 별개입니다. |

CPU·GPU·메모리 사용률은 각각의 자원 용량을 기준으로 하므로 더해서 100%가 되는 비율이 아닙니다. 순간적으로 높은 사용률이 나온다는 이유만으로 부품 구매나 교체 필요성을 확정하지 않습니다. GPU 추가 장착 시 실제 효과는 사용 프로그램의 다중 GPU 지원에도 달려 있습니다.

## 안정 분배: 공통 정책

대시보드의 **안정 분배**를 켜면 측정을 시작하고, 연동된 프로그램들이 같은 정책을 사용합니다. 앱마다 사용자가 임계값을 설정할 필요는 없습니다.

| 조건 | 다음 작업의 처리 |
| --- | --- |
| GPU 사용률 60% 이상 | CPU 경로를 지원하는 음성 검사는 CPU 선택. GPU 전용 단계는 다음 문장 시작 전 대기 |
| GPU 사용률 40% 이하가 5초 유지 | GPU 작업 재개 허용 |
| 최근 60초 내 GPU 사용률 60% 이상 관측 | CPU 지원 검사는 CPU 선택을 유지. 정상 CPU 검사 완료 시 60초 연장 |
| CPU 70% 이상, RAM 80% 이상 또는 여유 RAM 6GiB 미만 | 새로운 무거운 작업과 다음 문장 시작 대기 |
| 측정 중지·오류·오래된 값·제어기 연결 실패 | 임의로 장치를 선택하지 않고 대기 |
| 이미 무거운 연동 작업이 실행 중 | 다른 연동 작업은 차례 대기 |

이미 계산 중인 문장은 마친 뒤 경계에서 적용합니다. **60%는 분배 판단 기준이며 GPU 사용률의 하드웨어 상한이 아닙니다.** 실행 중인 계산에서 순간 100%가 나올 수 있습니다. CPU·GPU 사이에 모델을 강제로 옮기거나 드라이버·전력·클럭을 변경하지 않습니다.

연동 경로는 Whisper 음성 검사(CPU/CUDA), CosyVoice 합성(CUDA 유지와 구간 대기), 음성 전처리(CPU)입니다. 합성의 승인 음색·시드·품질 기준은 변경하지 않습니다. CPU 실행 시에는 최대 8개 계산 스레드를 사용합니다. 화면의 선택·완료 횟수는 실제 연동 작업 구간의 집계이며, 음성 파일 개수가 아닙니다.

Windows의 모든 외부 앱을 자동 변환하는 기능은 아닙니다. 개발자가 지원되는 작업 경계에 아래 SDK를 한 번 연동해야 하며, 이후 사용자는 중앙 스위치 하나로 제어합니다. 미연동 앱은 측정만 합니다. 현재 보유한 작업이 끝나기 전까지 다른 무거운 연동 작업을 허용하지 않으며, 임대 시간이 지나도 소유 프로세스가 살아 있으면 슬롯을 임의로 반환하지 않습니다.

### 개발자 연동

`resource_client.py`를 프로젝트에 포함하고 실제 계산을 수행하는 worker에서 사용합니다. SDK는 임의 명령 실행 API를 제공하지 않습니다. `examples/voice_stage_adapter.py`는 기존 순차 음성 worker에 넣는 어댑터 예시입니다.

```python
from resource_client import ResourceSession

with ResourceSession('whisper-asr') as resources:
    # 모델을 올리기 전에 resources.device / resources.threads를 적용합니다.
    # 기존 입력·모델 무결성 검사와 출력 품질 검증은 그대로 유지합니다.
    for item in pending_items:
        resources.checkpoint()  # 이미 실행 중인 계산이 끝난 경계에서 호출
        recognize_and_validate(item, device=resources.device,
                               threads=resources.threads)
```

CUDA 계산은 완료·동기화한 뒤 경계를 호출해야 합니다. 정상 세션 반환 전에 모델 참조와 CUDA 예약 메모리도 정리해야 합니다. 모델은 한 구간에서 선택한 장치를 유지하며, 중간에 CPU/CUDA를 전환하지 않습니다. SDK는 제어기 연결이 장시간 끊기면 명시적 오류를 내며, 기존 프로그램은 체크포인트를 보존하고 재개해야 합니다. 예외가 나면 임대를 유지하고 실제 worker가 종료된 뒤에만 회수합니다. 부모 프로세스에서 예외를 삼키고 같은 worker로 다음 작업을 시작해서는 안 됩니다. 분배를 끄면 다음 작업부터 기본 장치 정책을 사용하며 이미 시작한 작업은 마칩니다.

모든 소켓을 차단하는 오프라인 worker에는 같은 SDK의 `FileResourceSession`을 사용합니다. `resource_client.py`와 `resource_ipc.py`를 함께 포함합니다. 로컬 데이터 폴더의 서명된 JSON 요청·응답만 교환하므로 기존 네트워크 차단을 해제하지 않습니다. SDK와 정책은 같고 통신 경로만 다릅니다.

기록 파일 `governor.json`과 잠금 파일은 로컬 데이터 폴더에 저장합니다. 임대 기록이 손상되거나 다른 제어기가 같은 폴더를 사용하면 새 작업을 보류합니다. 측정값이나 사용자 정의 임의 명령을 외부 서버로 보내지 않습니다.

## 기록과 개인정보

측정 기록은 이 PC의 `%LOCALAPPDATA%\ResourceAnalyzer`에 저장하며, 최근 7일을 유지합니다. 수집과 저장에는 외부 AI API나 클라우드 전송을 사용하지 않습니다. 브라우저 서버는 로컬 주소 `127.0.0.1`에만 연결됩니다.

기록과 CSV에는 이 PC에서 실행한 프로그램 이름과 사용량이 담길 수 있습니다. 공유 전에 내용을 확인해 주세요. 측정 데이터·개인 설정·로그·로컬 검증 화면은 공개 소스 저장소에 포함하지 않습니다.

## 소스에서 실행하기

Python 3.11과 Windows 환경을 기준으로 개발합니다.

```powershell
git clone https://github.com/brownrigoon-commits/resource-analyzer.git
cd resource-analyzer
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe entrypoint.py
```

소스 실행에도 기본 포트 `7442`와 같은 로컬 데이터 폴더를 사용합니다. 같은 PC에서 이미 실행 중인 앱이 있다면 새 인스턴스 대신 기존 화면을 사용합니다.

실행 파일을 직접 빌드하려면 `./build.ps1`을 실행합니다. 빌드는 별도 `.venv-build` 환경을 만들고 `dist/ResourceAnalyzer.exe`를 생성합니다. GitHub Actions 자동 빌드는 [선택용 워크플로 템플릿](templates/windows-release.yml)을 제공합니다. 사용하려면 해당 파일을 저장소의 `.github/workflows/`에 넣어야 하며, 현재 릴리스는 로컬에서 빌드하고 실행을 검증한 파일입니다.

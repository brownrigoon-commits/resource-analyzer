# 자원 분석기

Qwen 화면 분석의 안정 분배 연동은 [0.6.0 연동 안내](docs/qwen-governor.md)를 참고하세요.

Windows PC의 CPU·메모리·디스크·GPU 사용량을 프로그램별로 확인하고 기록하는 로컬 앱입니다. 브라우저에서 실시간 사용량과 추이를 비교할 수 있습니다.

**다른 PC나 채팅에서 개발을 이어가려면 [작업 인계·환경 준비 안내](docs/continue-work.md)부터 읽어 주세요.**
소스·UI·의존성·빌드 절차는 이 저장소에, 설치/복원 파일은 E드라이브의 프로젝트별 버전 폴더에 보관합니다.

## 사용하기

PC 설치·배포 파일은 GitHub 코드와 별도로 E드라이브에도 버전별로 보관합니다.
백업·검증 명령과 복원 범위는 [PC 설치 파일 백업 절차](docs/pc-install-backups.md)를 참고하세요.

1. [GitHub Releases](https://github.com/brownrigoon-commits/resource-analyzer/releases)에서 Windows용 `ResourceAnalyzer.exe`를 다운로드합니다.
2. 앱을 실행하면 Chrome 등 기본 브라우저에서 시작 화면이 열립니다.
3. **내 컴퓨터 분석하기**를 누르면 분석 화면이 열립니다.

지원 대상은 **Windows 10/11 x64**입니다. 배포 실행 파일에는 실행 환경이 포함되므로 Python을 별도로 설치하지 않아도 됩니다. 현재 배포 파일에는 코드 서명이 없습니다. 내려받은 파일의 출처와 릴리스 정보를 확인해 주세요.

앱이 실행 중이면 이 PC의 브라우저에서 [분석기 열기](http://127.0.0.1:7442/)로 다시 접속할 수 있습니다. 브라우저 탭을 닫아도 앱이 실행 중이면 기록은 계속됩니다. PC를 재부팅한 뒤에는 앱을 다시 실행해야 합니다.

웹사이트만으로 PC 전체의 성능을 읽는 방식은 아닙니다. 설치한 로컬 앱이 Windows의 측정값을 수집하고, 같은 PC의 브라우저가 화면을 표시합니다.

## 확인할 수 있는 정보

- 약 1초 간격으로 새로 측정하는 CPU·메모리·디스크·GPU 사용량
- 프로그램별 CPU·메모리·GPU 엔진·입출력 사용량
- 최근 60초 실시간 그래프와 1시간·24시간·7일 기록
- 15초 단위 요약 저장과 CSV 내보내기
- 지속적인 높은 사용률, RAM·GPU 전용 메모리 여유를 살펴볼 수 있는 안내

수집 시간이 길어지거나 시스템이 바쁘면 실제 갱신 간격이 늘어날 수 있습니다. 숫자가 같더라도 새 측정값일 수 있습니다.

## 측정값을 읽는 방법

| 항목 | 의미와 범위 |
| --- | --- |
| CPU | PC 전체 논리 프로세서 용량을 100%로 표시합니다. 프로그램의 CPU 사용률도 같은 기준입니다. |
| 메모리 | 사용 중인 RAM과 사용 가능한 RAM을 표시합니다. 프로그램별 작업 메모리 합계와 PC 전체 사용량은 같지 않을 수 있습니다. |
| 디스크 | PC 전체의 물리 디스크 처리량과 프로그램별 논리 입출력은 다른 지표입니다. 캐시·장치 입출력 등으로 합계가 일치하지 않을 수 있습니다. |
| GPU 장치 | NVIDIA는 NVML 또는 `nvidia-smi`를 우선 사용합니다. AMD·Intel 등 Windows가 인식하는 하드웨어 GPU는 DXGI 장치 정보와 Windows GPU 성능 카운터를 사용합니다. 장치의 고유 식별자로 연결하며 이름·나열 순서로 사용률을 추측하지 않습니다. Windows 경로의 사용률은 장치에서 가장 바쁜 엔진 기준입니다. |
| 프로그램별 GPU | Windows GPU Engine 카운터에서 확인되는 프로세스의 엔진 사용량입니다. GPU 전체 지표와 기준이 달라 합계가 일치하지 않을 수 있습니다. 읽을 수 없는 값은 미지원 또는 확인 불가로 표시합니다. |
| 용량·속도 | 용량은 GiB, 입출력 속도는 MiB/s 기준입니다. 저장 공간 부족과 디스크 처리 속도 부족은 별개입니다. |

CPU·GPU·메모리 사용률은 각각의 자원 용량을 기준으로 하므로 더해서 100%가 되는 비율이 아닙니다. 순간적으로 높은 사용률이 나온다는 이유만으로 부품 구매나 교체 필요성을 확정하지 않습니다. GPU 추가 장착 시 실제 효과는 사용 프로그램의 다중 GPU 지원에도 달려 있습니다.

GPU가 여러 개면 상단 카드에는 측정된 사용률이 가장 높은 장치를 표시하고, **GPU와 저장 공간** 목록에 각 장치를 표시합니다.
전용 메모리와 시스템 RAM을 사용하는 공유 메모리는 구분합니다. 공유 메모리 한도는 추가 VRAM 용량이 아닙니다.
GPU 이름을 확인했어도 드라이버가 사용률·메모리·온도를 제공하지 않으면 해당 값은 **— / 확인 불가**로 남습니다.
Windows 카운터를 읽지 못했거나 새 측정을 기다리는 동안 0%로 대체하거나 이전 값을 재사용하지 않습니다.
사용률·메모리 경로는 별도 드라이버 설치나 관리자 권한 없이 읽습니다.
GPU 온도는 드라이버가 지원하는 경우 Windows D3DKMT API에서도 읽으며, DXGI LUID로 정확한 장치에 연결합니다.
Windows 사용률 API인 DXGI/PDH 자체는 온도를 제공하지 않습니다.

측정 기준: [Microsoft GPU 사용률 설명](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/),
[DXGI 장치 정보와 메모리 구분](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ns-dxgi-dxgi_adapter_desc1).

## 부품 온도

각 카드에는 해당 부품의 모델·규격을 표시합니다. 메모리는 장착 용량과 Windows 사용 가능 용량을 구분하고,
디스크 카드는 시스템 드라이브 모델과 연결된 다른 디스크 개수를 표시합니다. 이름에 마우스를 올리면
모듈·디스크 목록을 확인할 수 있습니다. 디스크 전송량·온도는 연결된 전체 장치의 측정 기준을 유지합니다.

사용량 숫자와 온도 배지는 각각 초록(여유), 노랑(주의), 빨강(높음)으로 표시합니다.
미측정·연결 지연은 중립색입니다. 아래는 표시용 참고 기준으로, 제조사의 허용 한계나 고장 판정이 아닙니다.
높은 사용률만으로 과열을 의미하지 않습니다. 색상은 안정 분배 설정을 변경하지 않습니다.

| 지표 | 노랑 시작 | 빨강 시작 |
| --- | --- | --- |
| CPU·GPU 사용률 / 가장 바쁜 물리 디스크 활동률 | 70% | 90% |
| 메모리 사용률 | 80% | 90% |
| CPU 온도 | 80°C | 85°C |
| GPU 온도 | 80°C | 90°C |
| 메모리 온도 | 65°C | 80°C |
| 디스크 온도 | 55°C | 65°C |

CPU 온도 색상은 보수적인 참고값입니다. 예를 들어 [AMD Ryzen 9 7950X3D 공식 사양](https://www.amd.com/en/products/processors/desktops/ryzen/7000-series/amd-ryzen-9-7950x3d.html)의 최대 동작 온도는 89°C이며 표시 기준과 구분해야 합니다.
디스크 부하 색상은 Windows PhysicalDisk의 `100 - % Idle Time` 중 가장 높은 값으로 판단합니다.
MiB/s만으로 장치별 처리 능력이나 포화 상태를 추정하지 않습니다.

## 네트워크 실시간 속도

네트워크 카드에서 현재 기본 경로 어댑터의 **유선·무선·가상/VPN 연결 종류**, 다운로드·업로드 **Mbps**,
PC와 공유기/스위치 사이의 연결 속도를 표시합니다. 실제 바이트 카운터 차이를 시간으로 나누며 LAN 트래픽도 포함합니다.
이 실시간 사용량 표시는 인터넷 회선 속도 벤치마크가 아니며, 그 자체로 외부 시험용 트래픽을 만들지 않습니다.
따라서 유휴 상태의 낮은 Mbps는 느린 회선이라는 의미가 아닙니다. 연결 속도 또한 인터넷 최대 속도와 다릅니다.

연결 종류는 어댑터 이름 대신 Windows의 물리 매체 정보로 확인합니다. 기본 경로 정보는 약 15초마다 갱신하고,
어댑터 전환·카운터 초기화·연결 끊김 때 이전 인터페이스의 속도를 이어 표시하지 않습니다.
어댑터 확인이 45초 이상 지연되면 미측정으로 표시합니다. 속도 색상은 어댑터 연결 속도 대비 송수신 비율입니다.
IP 주소·SSID·MAC 주소는 화면에 전달하거나 기록하지 않습니다.

### 인터넷 속도 테스트

네트워크 카드의 **속도 테스트** 버튼을 누르면 실제 테스트 데이터를 전송하여 다운로드·업로드 Mbps와
응답 지연(ms)을 측정합니다. **중지**로 멈추거나 **다시 측정**할 수 있습니다. 페이지를 열기만 해서는 실행하지 않습니다.
결과는 그 시각 PC에서 Cloudflare까지의 경로 성능이며, 공유기 연결 속도나 회선의 보장 최대치와 다릅니다.
다른 앱의 전송, Wi-Fi 상태, VPN, 서버 경로에 따라 달라질 수 있습니다.

공식 [@cloudflare/speedtest](https://github.com/cloudflare/speedtest) 1.14.2를 앱에 포함합니다.
테스트는 `speed.cloudflare.com`의 다운로드·업로드 끝점만 사용합니다. Cloudflare에는 연결에 필요한 공인 IP와
시험 트래픽이 전달되며, 라이브러리의 선택적 결과 수집(`logAimApiUrl`, `logMeasurementApiUrl`)은 비활성화했습니다.
개인 파일이나 측정 로그를 업로드하지 않으며 테스트 결과를 서버·GitHub에 저장하지 않습니다.

점진적으로 크기를 늘리는 기본 설정의 테스트 본문은 방향별 최대 약 82.1 MB(합계 164.2 MB)이며,
낮은 속도에서는 더 일찍 끝납니다. 재시도·프로토콜 부하는 별도입니다. 전체 제한 시간은 60초이고 개별 요청은
12초 제한을 둡니다. 중단·실패·시간 초과와 아직 완료되지 않은 숫자는 부분/잠정 결과로 표시합니다.
Web Locks를 지원하는 같은 브라우저·주소의 탭들은 한 번에 하나만 측정합니다.

배포 파일 재현은 `python tools/vendor_speedtest.py`로 공식 npm 배포본을 고정 해시로 확인합니다.
MIT 라이선스는 `third_party/Cloudflare-Speedtest-LICENSE.txt`에 포함되어 있습니다.

## 온도 센서 엔진

CPU·GPU·메모리·디스크 카드 안에 작은 온도를 표시합니다. GPU는 NVIDIA 측정값, Windows D3DKMT와
LibreHardwareMonitor 0.9.6의 AMD·Intel·NVIDIA 센서를 사용합니다. 나머지 부품도 같은 센서 엔진을 사용합니다.
여러 센서가 읽히면 그 부품의 최고 측정 온도를 표시하며, 마우스를 올리면 개별 센서를 확인할 수 있습니다.
GPU 온도는 측정 가능한 모든 GPU 센서 중 최고값이며, 사용률이 가장 높은 장치와 다를 수 있습니다.
**GPU 온도 센서** 목록에 실제 센서가 보고한 장치명과 온도를 따로 표시합니다.
이름이나 나열 순서로 온도를 다른 GPU에 붙이지 않습니다.
DIMM 온도에는 실제 센서값만 사용하고 경고 임계값·센서 해상도는 제외합니다.

CPU와 DIMM 접근에는 공식 PawnIO 드라이버와 센서 프로세스의 관리자 승인이 필요합니다.
드라이버를 처음 설치할 때는 함께 제공되는 `installers/PawnIO_setup.exe`를 실행하거나
`ResourceAnalyzer.exe --install-temperature-support`를 실행하고,
설치가 끝나면 분석기를 다시 시작합니다. 온도 프로세스만 관리자 권한으로 실행하며
웹 서버는 기존 권한과 로컬 주소를 사용합니다. 센서 엔진은 팬 속도·전압·클럭 설정을 변경하지 않습니다.

부품 자체에 센서가 없거나 펌웨어·드라이버에서 제공하지 않는 값은 다른 프로그램을 사용해도
확인할 수 없을 수 있습니다. 이 경우 온도를 추정하지 않고 확인 불가로 표시합니다.
센서 응답이 끊기면 이전 수치를 계속 표시하지 않습니다.

소스에서 온도 포함 실행 파일을 빌드하려면 `python tools/build_sensor_bridge.py`를 먼저 실행한 뒤
`pyinstaller ResourceAnalyzer.spec`를 실행합니다. 빌드 도구는 고정된 공식 배포본의 해시를 확인합니다.
배포 라이선스와 출처는 `third_party/`, 정적 분석 범위는 `docs/temperature-engine-review.md`에 있습니다.

## 안정 분배: 공통 정책

대시보드의 **안정 분배**를 켜면 측정을 시작하고, 연동된 프로그램들이 같은 정책을 사용합니다. 앱마다 사용자가 임계값을 설정할 필요는 없습니다.

| 조건 | 다음 작업의 처리 |
| --- | --- |
| GPU 사용률 60% 이상 | CPU 경로를 지원하는 음성 검사는 CPU 선택. GPU 전용 단계는 다음 문장 시작 전 대기 |
| GPU 사용률 40% 이하가 5초 유지 | GPU 작업 재개 허용 |
| 최근 60초 내 GPU 사용률 60% 이상 관측 | CPU 지원 검사는 CPU 선택을 유지. 정상 CPU 검사 완료 시 60초 연장 |
| CPU 70% 이상, RAM 80% 이상 또는 여유 RAM 6GiB 미만 | 새로운 무거운 작업과 다음 문장 시작 대기 |
| 측정 중지·오류·오래된 값·제어기 연결 실패 | 임의로 장치를 선택하지 않고 대기 |
| 이미 무거운 연동 작업이 실행 중 | 다른 연동 작업은 차례 대기 |

이미 계산 중인 문장은 마친 뒤 경계에서 적용합니다. **60%는 분배 판단 기준이며 GPU 사용률의 하드웨어 상한이 아닙니다.** 실행 중인 계산에서 순간 100%가 나올 수 있습니다. CPU·GPU 사이에 모델을 강제로 옮기거나 드라이버·전력·클럭을 변경하지 않습니다.

연동 경로는 Whisper 음성 검사(CPU/CUDA), CosyVoice 합성(CUDA 유지와 구간 대기), 음성 전처리(CPU)입니다. 합성의 승인 음색·시드·품질 기준은 변경하지 않습니다. CPU 실행 시에는 최대 8개 계산 스레드를 사용합니다. 화면의 선택·완료 횟수는 실제 연동 작업 구간의 집계이며, 음성 파일 개수가 아닙니다.

Windows의 모든 외부 앱을 자동 변환하는 기능은 아닙니다. 개발자가 지원되는 작업 경계에 아래 SDK를 한 번 연동해야 하며, 이후 사용자는 중앙 스위치 하나로 제어합니다. 미연동 앱은 측정만 합니다. 현재 보유한 작업이 끝나기 전까지 다른 무거운 연동 작업을 허용하지 않으며, 임대 시간이 지나도 소유 프로세스가 살아 있으면 슬롯을 임의로 반환하지 않습니다.

현재 안정 분배의 GPU 작업 경로는 NVIDIA/CUDA 연동을 기준으로 합니다. AMD·Intel의 사용량 표시는 CUDA 실행 지원을 뜻하지 않으며, Windows GPU 카운터만 있는 환경에서는 기존 보호 규칙에 따라 연동 작업을 보류합니다.

### 개발자 연동

`resource_client.py`를 프로젝트에 포함하고 실제 계산을 수행하는 worker에서 사용합니다. SDK는 임의 명령 실행 API를 제공하지 않습니다. `examples/voice_stage_adapter.py`는 기존 순차 음성 worker에 넣는 어댑터 예시입니다.

```python
from resource_client import ResourceSession

with ResourceSession('whisper-asr') as resources:
    # 모델을 올리기 전에 resources.device / resources.threads를 적용합니다.
    # 기존 입력·모델 무결성 검사와 출력 품질 검증은 그대로 유지합니다.
    for item in pending_items:
        resources.checkpoint()  # 이미 실행 중인 계산이 끝난 경계에서 호출
        recognize_and_validate(item, device=resources.device,
                               threads=resources.threads)
```

CUDA 계산은 완료·동기화한 뒤 경계를 호출해야 합니다. 정상 세션 반환 전에 모델 참조와 CUDA 예약 메모리도 정리해야 합니다. 모델은 한 구간에서 선택한 장치를 유지하며, 중간에 CPU/CUDA를 전환하지 않습니다. SDK는 제어기 연결이 장시간 끊기면 명시적 오류를 내며, 기존 프로그램은 체크포인트를 보존하고 재개해야 합니다. 예외가 나면 임대를 유지하고 실제 worker가 종료된 뒤에만 회수합니다. 부모 프로세스에서 예외를 삼키고 같은 worker로 다음 작업을 시작해서는 안 됩니다. 분배를 끄면 다음 작업부터 기본 장치 정책을 사용하며 이미 시작한 작업은 마칩니다.

모든 소켓을 차단하는 오프라인 worker에는 같은 SDK의 `FileResourceSession`을 사용합니다. `resource_client.py`와 `resource_ipc.py`를 함께 포함합니다. 로컬 데이터 폴더의 서명된 JSON 요청·응답만 교환하므로 기존 네트워크 차단을 해제하지 않습니다. SDK와 정책은 같고 통신 경로만 다릅니다.

기록 파일 `governor.json`과 잠금 파일은 로컬 데이터 폴더에 저장합니다. 임대 기록이 손상되거나 다른 제어기가 같은 폴더를 사용하면 새 작업을 보류합니다. 측정값이나 사용자 정의 임의 명령을 외부 서버로 보내지 않습니다.

## 기록과 개인정보

네트워크 카드 아래의 **주의·높음 원인 보고**는 카드와 같은 사용량·온도 기준을 적용하고 약 1초마다 갱신합니다.
현재 기준을 넘은 항목만 보여 주며, CPU·GPU·메모리에는 같은 시점의 상위 사용 프로그램을 함께 표시합니다.
측정값만으로 확정할 수 없는 고장·발열 원인이나 작업 내용을 추측하지 않습니다. 정상 복귀·측정 지연 시 기존 경고를 제거합니다.

측정 기록은 이 PC의 `%LOCALAPPDATA%\ResourceAnalyzer`에 저장하며, 최근 7일을 유지합니다. 수집과 저장에는 외부 AI API나 클라우드 전송을 사용하지 않습니다. 브라우저 서버는 로컬 주소 `127.0.0.1`에만 연결됩니다.

기록과 CSV에는 이 PC에서 실행한 프로그램 이름과 사용량이 담길 수 있습니다. 공유 전에 내용을 확인해 주세요. 측정 데이터·개인 설정·로그·로컬 검증 화면은 공개 소스 저장소에 포함하지 않습니다.

## 소스에서 실행하기

Windows x64와 Python 3.12 x64를 기준으로 검증합니다(Python 3.11 이상 허용).

```powershell
git clone https://github.com/brownrigoon-commits/resource-analyzer.git
cd resource-analyzer
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe entrypoint.py
```

소스 실행에도 기본 포트 `7442`와 같은 로컬 데이터 폴더를 사용합니다. 같은 PC에서 이미 실행 중인 앱이 있다면 새 인스턴스 대신 기존 화면을 사용합니다.

준비 명령은 Python 의존성과 해시로 확인한 온도 센서 엔진을 함께 준비합니다. 드라이버를 설치하거나 앱을 실행하지는 않습니다.

실행 파일을 직접 빌드하려면 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`을 실행합니다.
별도 `.venv-build` 환경과 센서 엔진을 준비하고 `dist/ResourceAnalyzer.exe`, `dist/SHA256SUMS.txt`를 생성합니다.
[Windows 빌드 워크플로](.github/workflows/windows-build.yml)는 main push·PR·수동 실행에서 검사와 빌드를 수행합니다.
Actions 산출물은 30일 보관되므로 영구 보관은 버전별 E 백업과 게시된 Releases를 사용합니다.

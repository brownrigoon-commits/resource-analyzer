누적 보관, 접기 상태 기억, 페이지 탐색과 네트워크 위 배치는 그대로다.
새 기록의 `program`/`task`는 당시 관측값으로 저장한다. 연동 단계명은 수집 전후 같은 임대이며 해당 프로그램 그룹에
PID·정확한 생성 시각이 일치하는 소유 프로세스가 있을 때만 연결한다. PDH의 문자열 identity를 생성 시각으로 사용하지 않는다.
그 밖에는 실행 스크립트명 또는 GPU 엔진 종류를 사용하고 세부 작업은 추측하지 않는다.
온도 항목의 프로그램은 동시 관측값이며 물리적 발열 원인 확정이 아니다. 이전 기록은 원래 저장된 증거에서 프로그램명만 복원한다.
검증: Python 85개, JavaScript 17개 통과. 개인 측정과 분리한 합성 브라우저에서 두 줄 배치와
기존 기록의 프로그램 표시·작업 미확인 처리를 확인했다. 개인 경고 DB에 시험 기록을 넣지 않았다.
0.6.3 실행 패키지를 깨끗한 소스 커밋 `b02e3022674242e1e7edef787c2de076d82ee307`에서 빌드했다.
바탕화면 실행 파일 복사와 SHA-256 검증, 적용 전 E 설치 백업을 완료했다.
에이전트의 네이티브 갱신 실행이 자동 승인 검토에서 차단되어 사용자가 패키지의 `Update-ResourceAnalyzer.cmd`를 직접 실행했다.
적용 후 기본 포트의 실제 실행 버전 0.6.3, 수집 활성화, 신규 표본 시각 진행과 지연 없음,

기존 브라우저 탭에서 이전 화면이 남으면 새로고침한다. 이번 적용 후 실제 개인 화면의 브라우저 자동 검증은 수행하지 않았다.
일반 바탕화면 실행은 기존 앱에 연결될 수 있으므로 이미 실행 중인 버전 교체에는 패키지의 갱신 도구를 사용한다.

## 누적 경고 기록·디스크 용량 — 2026-10-22 (0.6.2)

현재 요구는 경고를 정상 복귀 때 없애는 것이 아니라 발생 기록을 계속 보존하는 것이다. 아래 0.6.1 동작은 과거 버전 설명이다.
`warning_history.py`가 수집기에서 브라우저와 독립적으로 `warning-events.sqlite3`에 매 측정 시 커밋한다.
이 DB에는 자동 삭제가 없으며 7일 보관인 `usage.sqlite3`와 분리된다. 앱이 수집하지 않는 동안에는 새 경고를 관측할 수 없다.
연속된 동일 수준·주요 프로그램은 한 구간에 최고값·최근값·관측 횟수를 갱신한다. 수준·주요 프로그램 변경 또는 재발은 새 기록이다.
정상 복귀·측정 중단·앱 재시작을 구분하며 측정 중단을 정상 복귀로 표현하지 않는다.
화면은 50건씩 커서로 탐색하고, 접기·펼치기 선택은 해당 브라우저에 기억한다. 화면 연결 실패 시 이미 읽은 기록을 지우지 않는다.
기록 패널은 네트워크보다 위에 있다. 디스크 카드 용량은 시스템 드라이브 문자와 볼륨을 정확히 매칭하며 GiB 단위다.
카드와 저장 기록의 공통 기준은 `static/resource-rules.mjs`의 ES-module JSON 객체다. 형식을 임의 JavaScript 코드로 바꾸지 않는다.
이 DB·원본 측정 데이터는 공개 GitHub와 일반 E 설치 백업에 포함하지 않는다. 개인 기록 백업은 별도 범위를 정해야 한다.
검증: `python -m unittest test_warning_history test_onboarding test_launcher_http test_updater test_monitor` 및
`node --test test_warning_history_ui.mjs test_resource_report.mjs test_speedtest.mjs`.

완료 검증: Windows Python 검사 81개와 JavaScript 검사 15개 통과. 합성 브라우저 화면에서 정상 복귀 기록이 남는 것,
접기·펼치기, 새로고침 후 접힘 선택 유지, 기록이 네트워크보다 위에 있는 것과 디스크 카드의 실제 볼륨 매칭을 확인했다.
이 PC의 기본 포트는 실제 0.6.2로 정상 갱신했고 수집 활성화·새 측정 시각 진행·저장소 생성·기록 API 정상 응답을 확인했다.
이전 자원 요약과 안정 분배 설정은 유지했다. 바탕화면 실행 파일도 갱신했으며 SHA-256을 검증했다.
개인 경고 DB에 합성 시험 기록을 넣지 않았다. 배포 전의 순간 경고는 소급 생성하지 않는다.
실행 패키지와 Git 소스 bundle은 기존 E 프로젝트 구조의 새 체크포인트에 크기·SHA-256 검증 후 보관했다.
실행 파일의 빌드 커밋은 `BUILD-INFO.txt`를 기준으로 하며, 인계 문서만 변경된 최신 Git 커밋과 다를 수 있다.

## 가져오기와 준비

지원 환경은 Windows 10/11 x64, Git, Python 3.12 x64(검증 기준)다. Python 3.11 이상을 허용한다.
JavaScript 테스트에는 Node.js 22 이상이 필요하고, 앱 실행에는 Node.js가 필요하지 않다.
인터넷 연결로 Python 패키지와 아래 고정 센서 배포본을 가져온다.
공식 PawnIO 2.1.0 설치 파일·대응 소스·라이선스는 `installers/`에 포함되어 별도 다운로드 없이 사용할 수 있다.

```powershell
git clone https://github.com/brownrigoon-commits/resource-analyzer.git
cd resource-analyzer
git status --short
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe entrypoint.py
```

`python`이 다른 버전이면 `setup.ps1 -Python <Python-3.12-python.exe>`를 사용한다.
준비 스크립트는 의존성 설치, 해시로 확인한 센서 DLL 준비, Windows에 포함된 .NET Framework 컴파일러로
SensorBridge 빌드까지 수행한다. 드라이버 설치·관리자 프로세스 실행·기존 분석기 재시작은 하지 않는다.
전체 앱 빌드는 다음 한 명령으로 준비 단계까지 수행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
# dist/ResourceAnalyzer.exe, dist/SHA256SUMS.txt
# dist/BUILD-INFO.txt (버전·소스 커밋·미커밋 변경 여부·시각·실행 파일 해시)
# dist/BUILD-DEPENDENCIES.txt (해당 빌드에 사용한 Python 패키지 버전)
```

같은 PC에서 실행 중인 분석기가 있으면 기본 포트 7442로 기존 화면을 연다.
독립 검증에는 다른 포트와 데이터 폴더를 **둘 다** 지정한다.

```powershell
.\.venv\Scripts\python.exe entrypoint.py --port 17442 --data-dir .\local\smoke --no-browser
# 브라우저에서 http://127.0.0.1:17442/ 를 연다.
# 검증 인스턴스만 종료:
.\.venv\Scripts\python.exe entrypoint.py --port 17442 --data-dir .\local\smoke --stop --no-browser
```

기록은 기본적으로 `%LOCALAPPDATA%\ResourceAnalyzer`에 저장된다. 새 PC에서 기록이 비어 있는 것은 정상이다.
기록·비밀 설정은 소스 복제에 포함되지 않는다. 이 앱에는 API 키나 로컬 ML 모델이 필요하지 않다.

  이전 값이나 가짜 0%를 표시하지 않는다. 전용 메모리와 공유 RAM은 구분한다.

## 작업 종료 시 보관

사용자 변경만 커밋·push하고 원격 커밋을 확인한다. 실행 가능한 빌드는 아래처럼 E에 체크포인트로 남긴다.
기존 외부 출력 폴더를 포함하는 방법은 [백업 절차](pc-install-backups.md)를 참고한다.

```powershell
.\.venv-build\Scripts\python.exe tools/backup_installables.py --package-dir dist
```

이 명령은 상주 서비스가 아니다. 실패하면 GitHub와 E 중 어떤 보관이 미완료인지 명시한다.

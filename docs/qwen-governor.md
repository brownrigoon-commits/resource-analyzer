# Qwen 화면 분석의 안정 분배

자원 분석기 0.6.0과 LEARN & WORK studio의 `apps/local-ai/resource-governor.mjs`를 함께 사용한다.
기존 버전에는 Qwen 단계가 등록되어 있지 않으며 새 클라이언트는 확인되지 않은 기본 GPU 실행으로 우회하지 않는다.

| 스위치·상태 | 화면 분석 | 결과 요약 |
| --- | --- | --- |
| 꺼짐 | 기본 GPU (`num_gpu:-1`) | 기본 GPU |
| 켜짐·GPU 여유 | CPU + GPU 혼합 (`num_gpu:8`, CPU 최대 8스레드) | CPU (`num_gpu:0`) |
| 켜짐·GPU 60% 이상 | CPU | CPU |
| CPU 70% 이상 / RAM 80% 이상 / RAM 여유 6GiB 미만 / 측정 중단 | 새 요청 대기 | 새 요청 대기 |

`num_gpu`는 GPU에서 실행할 **모델 층 수**이며 사용률 제한 퍼센트가 아니다.
혼합 실행 중에도 짧게 GPU가 높아질 수 있다. 실행 중인 모델의 장치는 강제로 바꾸지 않고 다음 화면/요약 경계에서 선택한다.
표시되는 CPU 선택·완료 횟수에는 CPU가 실제 계산하는 혼합 배정도 포함한다. 실행 장치는 `CPU + GPU 분담`으로 구분한다.

스튜디오는 로컬 신원·CSRF·작업 프로세스 시작 시각을 확인해 단계별 임대를 요청하고 엔진 옵션을 적용한다.
5초 간격으로 상태를 갱신하며, 취소·실패 시에도 모델 해제를 확인한 뒤에만 임대를 반환한다.
해제를 확인하지 못하면 임대를 유지하므로 다른 작업이 GPU로 조용히 재시작하지 않는다.
이미지나 프롬프트, 분석 내용, 연결 토큰은 분배 API·공개 저장소에 전달하지 않는다.

CPU 경로는 느리므로 연동된 분석의 전체 제한은 최대 10분이다. 비연동 분석의 기존 180초 제한은 유지한다.
연속 분석은 이전 작업을 기다리며 중복 계산하지 않는다. 자료 범위·동의·출력 검증·사용자 검토 조건은 유지한다.

## 엔진 경로 검증 (2026-10-21)

합성 배송 화면에서 같은 주문번호 `DEMO-1001`을 읽었다. 실제 사용자 화면은 시험에 쓰지 않았다.
Ollama 0.40.6 / Qwen3-VL 4B / CPU 8스레드 / 문맥 2048 / 최대 출력 24토큰으로 짧게 검사했다.

- 혼합 경로에서 CPU 계산과 GPU의 일부 모델 배치를 확인했다.
- CPU 전용 경로는 엔진의 모델 GPU 메모리 0바이트를 확인했다.
- 두 시험 모두 주문번호를 정확히 반환했다. 화면 6장 전체의 정확도·시간을 보장하는 검증은 아니다.
- PC 자원 실측 원본은 공개 저장소에 포함하지 않는다.

공식 옵션 근거: [Ollama v0.40.6 Runner 옵션](https://github.com/ollama/ollama/blob/v0.40.6/api/types.go),
[런타임 옵션 API](https://github.com/ollama/ollama/blob/main/docs/api.md#generate-request-with-options).

적용 검증은 별도로 기록한다. 소스 수정만으로 이미 실행 중인 앱이 갱신되지는 않는다.
